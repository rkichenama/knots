How should crossing O/U be determined?

Current code reads coding[j] directly — but Knot already pre-computes the correct O/U per half-cycle via topCodingPattern / botCodingPattern. Three approaches:

A

Read from halfCycle.runs directly (Recommended)

Each HalfCycle has a .runs[] array of 'O' / 'U' strings — the exact sequence computed by Knot.fillHalfCycles() including the progressive CBN gating and sobre flip. Map runs[j] directly to piece uo.

Pros

  • Single source of truth — no re-derivation
  • Sobre, pattern, and CBN gating all correct automatically
  • Simplest code in computeMandrelPieces

Cons

  • Requires runs[] to be populated (free-run HCs have no runs — need null handling)
B

Read from topCodingPattern / botCodingPattern arrays

These arrays on Knot hold the final O/U per crossing position (already sobre-flipped). Even-indexed HCs use topCodingPattern, odd use botCodingPattern (reversed). Requires figuring out which index maps to which piece.

Pros

  • Sobre already baked in

Cons

  • Index mapping is non-trivial (top vs bot, direction reversal)
  • Still misses CBN gating (not all positions active in early HCs)
C

Re-derive from coding + sobre in computeMandrelPieces (current)

Keep reading coding[j] and applying the sobre flip manually. Fix the direction logic for left-going HCs.

Pros

  • No dependency on HalfCycle internals

Cons

  • Ignores CBN gating — early HCs have fewer active crossings than parts-1
  • Sobre flip logic duplicated (already in Knot)
  • Left-going direction reversal is subtle and currently wrong
